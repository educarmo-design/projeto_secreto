# 20260812_0010 — N08 (Motor de Exceções, dupla via) + N10 (Prescrição) + N11 (Meta Self-Service)

Log de Máquina (Regra 10.3 — append-only). Execução integrada dos 3
domínios: uma única RPC no banco (`validar_e_salvar_meta`) serve as duas
vias — Painel Web (profissional, N10, consertador/alerta) e App Flutter
(atleta, N11, Trava ANVISA).

## Parte 1 — Banco de dados

Migration `20260812110000_n08_motor_excecoes_n10_n11_objetivos_alimentares.sql`:

- Tabela `objetivos_alimentares(id, usuario_id, profissional_id nullable,
  tipo_dia default 'PADRAO', calorias_alvo, proteina_g, carbo_g, gordura_g,
  data_criacao, vencimento_em, status_vigencia)`. **SEM policy de INSERT/
  UPDATE para `authenticated`** — a ÚNICA porta de escrita é a RPC abaixo
  (mesmo espírito de `papeis_permissoes`), tornando impossível contornar o
  Motor de Exceções inserindo direto na tabela.
- Trigger `objetivos_alimentares_trg_versionar` (`before insert`, mesmo
  padrão de `anamneses_trg_versionar`): no máximo 1 meta `ativo` por
  `(usuario_id, tipo_dia)` — a antiga vira `historico`.
- RPC `validar_e_salvar_meta(p_payload jsonb, p_is_profissional boolean)`
  — a dupla via numa função só:
  - `p_is_profissional = true` (N10): exige vínculo ativo com o paciente
    (ou ser o próprio, ou admin); violação clínica vira `avisos`/
    `violacao_clinica` na resposta, **nunca bloqueia** o INSERT.
  - `p_is_profissional = false` (N11): `usuario_id` é sempre `auth.uid()`
    (nunca lido do payload — evita um atleta criar meta pra outra
    pessoa). Antes da validação clínica, 2 travas adicionais:
    1. **Prioridade B2B** (Restrição explícita da tarefa): se já existe
       meta `ativo` do mesmo `tipo_dia` com `profissional_id` preenchido
       → `RAISE EXCEPTION N08_PRIORIDADE_PROFISSIONAL` (o atleta não
       sobrescreve uma prescrição).
    2. **Carência mensal**: se existe meta AUTO-criada (`profissional_id
       is null`) nos últimos 30 dias → `RAISE EXCEPTION
       N08_CARENCIA_MENSAL`. Só conta metas self-created — uma
       prescrição profissional não consome a cota do atleta.
    3. Violação clínica → `RAISE EXCEPTION N08_TRAVA_CLINICA` (Hard
       Block, o INSERT nunca acontece).
  - Regras clínicas (as mesmas para as duas vias): chama
    `calcular_motor_metabolico` (N07) internamente pra obter TMB e peso;
    `(gordura_g / peso) < 0.6` OU `calorias_alvo < tmb` OU
    `calorias_alvo > tmb * 2.5` → violação. Se TMB/peso indisponíveis
    (perfil incompleto), a validação numérica é pulada — isso NÃO é uma
    violação (nada foi violado, é desconhecido), só um aviso informativo.
  - Mensagens prefixadas (`N08_...`) — o client detecta por
    `error.message.contains(...)`.

**Verificado funcionalmente** (script descartável, removido após rodar) com
9 asserções cobrindo: profissional prescrevendo valores extremos (sucesso +
avisos), profissional represcrevendo sem cooldown + versionamento (meta
antiga vira histórico), atleta bloqueado por prioridade profissional,
atleta bloqueado por trava clínica (nada gravado), atleta com valores
válidos (sucesso), atleta bloqueado por carência mensal na segunda
tentativa. Todas passaram.

## Parte 2 — Painel Web React (N10)

- Novo `PrescricaoView.tsx`, montado em `PatientDetails.tsx` (abaixo do
  `MotorMetabolicoCard`, RELATÓRIO 20260812_0009): cards das metas ativas,
  formulário (Tipo de Dia, Calorias, Proteína/Carbo/Gordura, Vencimento
  default +7 dias), histórico (últimas 10). Botão "Copiar Último" em cada
  card e ao lado do campo Tipo de Dia (quando já existe uma meta ativa
  daquele tipo) — preenche o formulário sem redigitar.
- Salvar chama `validar_e_salvar_meta` com `p_is_profissional: true`; se a
  resposta vier com `violacao_clinica: true`, um banner amarelo lista os
  avisos traduzidos — o botão de Salvar nunca fica desabilitado por causa
  disso (a RPC já nunca bloqueia esse caminho).

## Parte 3 — App Flutter (N11)

Novo em `lib/features/nutricao/`:
- `data/repositories/meta_bem_estar_repository.dart`: busca a última meta
  própria (carência), a meta ativa do profissional (prioridade B2B),
  sugestão de calorias (`gasto_sedentario` do Motor N07) e `salvarMeta`
  (chama a RPC com `p_is_profissional: false`, encapsula erros em
  `MetaBloqueadaException` com um `MotivoBloqueioN08` tipado).
- `presentation/pages/meta_bem_estar_page.dart`: 3 estados de bloqueio
  além do formulário — **carência** (tela inteira travada, mostra a data
  de liberação), **sob acompanhamento profissional** (tela travada,
  mostra a meta vigente), e **trava clínica** (modal vermelho, só ao
  tentar salvar, com `showDialog`/`AlertDialog`). Botão "Usar sugestão"
  preenche calorias com base no TMB. Entrada de navegação em
  `configuracoes_perfil_page.dart`.
