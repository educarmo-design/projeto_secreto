# 20260810_0006 — Corrige double-counting de distância + Tela de Perfil (altura_cm)

- **Tarefa**: débito técnico em `HealthSyncService` (distância) + tela nova de formulário Flutter integrada ao Supabase.
- **Branch**: `feature/n17-n18-telemetria-persistida`.

## Parte 0 — auditoria antes de mexer

- Confirmado lendo `HealthSyncService._mesclarPorDia`: `distancia_metros` ainda usava `somar()` (soma pura entre fontes) — o mesmo double-counting já corrigido para `passos`/`calorias_ativas` numa tarefa anterior (`20260810_0001`/`0002`) nunca tinha sido replicado pra distância. Risco mapeado pelo fundador se confirmou no teste físico.
- `DISTANCE_WALKING_RUNNING` e `DISTANCE_DELTA` mapeiam para o MESMO campo (`distanciaMetros`, `HealthPayloadModel.fromHealthDataType`) — a correção precisa cobrir os dois tipos brutos, não só um.
- Já existia uma tela chamada "Perfil" (`ConfiguracoesPerfilPage`, 4ª aba do BottomNavigationBar — troca de perfil Atleta/Guardião, convites, logout). O pedido do prompt ("ícone de Perfil na AppBar ou BottomNavigation") já está coberto por essa aba; a integração natural e consistente com o padrão já usado (`heart_rate_test_item`/`weight_test_item`/`sleep_test_item`, todos `ListTile` → `Navigator.push` → `MaterialPageRoute`) é um novo item de lista dentro dela, não uma 5ª aba nem um ícone extra na AppBar.
- RLS/GRANT de `perfis_usuarios` já cobriam UPDATE do próprio dono (`perfis_usuarios_update_own`, `auth.uid() = id`, confirmado em `20260706191827_core_schema.sql`) e `grant ... update ... to authenticated` (`20260713140000_saneamento_grants_e_unificacao_rls.sql`) — nenhuma migration nova necessária, `altura_cm` já existe desde `20260811130000`.
- Confirmado que `nome`/`telefone`/`email` de `perfis_usuarios` são PII cifrada em repouso (D2) — o novo repositório usa `.select('altura_cm')`, nunca `.select()` (todas as colunas), para não puxar ciphertext à toa.

## Correção da distância

- `HealthSyncService._mesclarPorDia`: novo acumulador `distanciaPorDiaFonte`, mesmo padrão de `passosPorDiaFonte`/`caloriasPorDiaFonte` — soma dentro de uma fonte ao longo do dia, depois `aplicarMaiorFonte` pega o maior total entre fontes (nunca a soma entre fontes).
- Teste novo em `health_sync_service_test.dart`: celular (`Health Connect`, 4800m) + Garmin (`Garmin Connect`, 5200m) no mesmo dia → resultado tem que ser 5200, nunca 10000.
