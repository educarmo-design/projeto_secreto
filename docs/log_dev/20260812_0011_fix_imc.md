# 20260812_0011_fix_imc — Correção: IMC não calculava para atleta1000@teste.com

Log de Máquina (Regra 10.3 — append-only). Investigação e correção de bug
reportado pelo fundador: IMC não calcula para `atleta1000@teste.com`.

## Auditoria — o que foi checado, nesta ordem

1. **Tela de salvamento** (`perfil_usuario_page.dart` +
   `perfil_usuario_repository.dart`): a função de Salvar já envia a Altura
   para `perfis_usuarios` corretamente (não existe caminho pra Peso nessa
   tela — Peso nunca é digitado no app, só chega via sync do wearable em
   `metricas_saude_diarias`, ver achado 2 abaixo). Já existia tratamento de
   erro com `SnackBar` vermelho (`on PostgrestException catch`/`catch`
   genérico) — isso não precisou ser adicionado, só verificado.
2. **Estado real do usuário no banco** (consulta direta, service role,
   script descartável removido após rodar): `atleta1000@teste.com` **tem**
   `auth.users` e **tem** `metricas_saude_diarias` cheia de dados reais do
   Garmin (`origem: com.garmin.android.apps.connectmobile`, peso
   sincronizado em 2026-08-10: 80.6kg) — não é uma conta de teste vazia.
   Mas **não tem NENHUMA linha em `perfis_usuarios`** — `select * from
   perfis_usuarios where id = ...` devolve `null`.
3. **Causa raiz**: `atualizarAlturaCm`/`atualizarDataNascimento`/
   `atualizarSexoBiologico` usavam `.update({...}).eq('id', usuarioId)`.
   Um `UPDATE` cujo `WHERE` não casa NENHUMA linha **não é um erro** para
   o Postgrest — ele devolve sucesso (0 linhas afetadas, sem exceção). Com
   `perfis_usuarios` vazia para este usuário, TODO save de altura "tinha
   sucesso" e não gravava nada — nenhum `try/catch` jamais disparava
   porque não havia exceção nenhuma pra capturar. É um "silent failure"
   estrutural, não uma exceção engolida.
4. **Cálculo de IMC**: `_aplicarInferenciasCruzadas`
   (`health_sync_service.dart`) já converte cm→m corretamente e já é
   null-safe (`if (linha['imc'] == null && peso != null && peso > 0)`) —
   sem bug ali. O problema real é mais básico: **nenhuma tela do app
   Flutter jamais mostrou um IMC calculado ao vivo** — o único IMC exibido
   em qualquer lugar era a coluna `metricas_saude_diarias.imc`, pré-
   calculada no momento do sync (que precisa de altura DISPONÍVEL
   naquele instante), num quadro de debug (`historico_telemetria_page.dart`).
   Sem altura salva (achado 3), o `imc` nunca era calculado no sync, e não
   havia lugar nenhum no app que recalculasse isso client-side.

## Correção

- **`perfil_usuario_repository.dart`**: os 3 métodos de escrita
  (`atualizarAlturaCm`/`atualizarDataNascimento`/`atualizarSexoBiologico`)
  trocaram `.update()` por `.upsert({'id': usuarioId, ...}, onConflict:
  'id')` — cria a linha em `perfis_usuarios` se ela não existir, atualiza
  se existir. Seguro: a RLS `perfis_usuarios_insert_own`
  (`20260714100000_add_approval_workflow.sql`) só exige `auth.uid() = id`
  + os defaults seguros de `eh_profissional`/`status_aprovacao`/
  `is_admin`, nenhum dos quais este repositório tenta sobrescrever — **sem
  migration nova** (a RLS já permitia isso, só o código Dart não usava o
  caminho certo).
- Novo `buscarUltimoPesoKg()` no repositório — última leitura de
  `metricas_saude_diarias.peso_kg` (a mesma fonte que
  `_aplicarInferenciasCruzadas` usa).
- **`perfil_usuario_page.dart`**: IMC ao vivo, calculado no cliente
  (`peso / (altura_cm/100)²`, null-safe em cada etapa) e exibido logo
  abaixo do campo de altura — recalcula a CADA dígito digitado (listener
  no `TextEditingController` + `setState`), não só depois de salvar. Três
  estados: sem peso sincronizado (pede pra sincronizar o wearable), sem
  altura válida digitada (pede pra preencher), ou o valor com a data do
  peso usado ("baseado no peso de dd/mm").

## Verificação

- **Reproduzido e confirmado o fix contra o banco real**: script
  descartável (removido após rodar) criou um usuário de teste no MESMO
  estado quebrado de `atleta1000@teste.com` (`auth.users` existe,
  `perfis_usuarios` não), autenticou como ele (sessão real, não
  service_role) e confirmou que o `.upsert()` cria a linha respeitando a
  RLS, com `altura_cm` gravado e os defaults seguros
  (`eh_profissional=false`, `status_aprovacao=pendente`, `is_admin=false`).
- `flutter analyze lib/features/dashboard`: baseline de 5 issues,
  inalterada.
- `flutter test test/features/dashboard/`: 147 testes, todos passando (7
  novos: 3 no repositório cobrindo upsert/`buscarUltimoPesoKg`, 4 na tela
  cobrindo os 3 estados do IMC ao vivo + a reatividade ao digitar).
- `flutter build apk --debug`: build concluído, `.apk` verificado em
  disco.

## Fora do escopo desta tarefa (registrado, não resolvido aqui)

- O IMC dos dias JÁ sincronizados antes deste fix continua `null` no
  histórico (`historico_telemetria_page.dart`) — a correção vale pra
  saves/syncs daqui pra frente; recalcular retroativamente exigiria uma
  nova Carga de 30 dias (o botão de debug "FORÇAR CARGA 30 DIAS" já
  existente cobre isso, sem precisar de código novo).
- Não foi adicionado um campo de Peso manual no app — Peso continua só
  vindo do wearable, por decisão de arquitetura já registrada em tarefas
  anteriores; o achado real desta tarefa foi que a altura nunca chegava a
  salvar, não que faltava um campo de peso.
